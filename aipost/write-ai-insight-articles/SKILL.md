# AI 观察文章写作

## 核心目标

把已经成立的角度写成一篇准确、清楚、能让人读下去，也像一个具体的人写出来的中文文章。

维持四层关系：

> 事实决定文章能不能成立。  
> 角度决定读者重新看见什么。  
> 解释决定复杂内容能不能被理解。  
> 文笔决定这种理解能不能被感受到和记住。

默认风格是清楚、克制、自然，带一点冷观察。先让事实出现，再让判断从事实后面长出来；从具体细节进入，揭开隐藏的一层，最后落到人的处境、选择、责任或新的理解。

文章可以锋利，但不靠刻薄制造锋利；可以有情绪，但不替读者喊情绪；可以讨论趋势，但不把一次发布写成时代转折。

## 职责边界

开始写作前，尽量确认已有：

- 主角度一句话
- 事实锚点与来源归属
- 主要读者及其关心的问题
- 开头细节、核心解释与结尾落点
- 需要保留的条件、不确定性与风险边界

缺少主角度时，先提炼一个保守的临时角度并明确说明，不在正文里同时尝试多个方向。关键事实缺失且会改变结论时，先指出缺口；不要用常识、想象或流畅表达填补证据。

本技能只负责写作和修改：

- 不重新判断素材是否值得选。
- 不擅自把既定角度改成更刺激的题目。
- 不主动扩展为完整论文解读、行业研究或竞品报告。
- 不把来源一方的宣传口径写成已验证事实。
- 不为了凑篇幅添加百科背景、功能清单或泛泛影响。
- 不默认生成摘要、封面、口播、图表、排版 HTML 或发布配置。

用户要求直接成稿但只提供原始素材时，可以在内部选择最扎实的单一角度后继续，不展示冗长推理。

## 第一步：锁定文章承诺

写作前在内部完成三句话：

1. **发生了什么**：用一句可核验的话压缩事实。
2. **真正变化了什么**：不是功能名称，而是能力边界、工作方式、权力关系、成本、责任或选择发生了什么变化。
3. **读者看完多得到什么**：一项新的理解、判断、辨别方法或现实参照。

第二句与第三句不能只是第一句的换写。如果读者最终只知道产品新增了哪些功能，稿件仍是资讯搬运。

文章只履行一个主要承诺。不要同时解释技术原理、评价公司战略、预测行业格局、讨论职业焦虑和提供使用教程。

## 第二步：选择叙事发动机

从已有角度中选择最适合的一种主要推进力量，全篇保持稳定。

### 变化

适合能力升级、工作流改造和产品形态变化。围绕“以前怎样，现在怎样，转变发生在哪里”展开。

不要把版本更新天然写成范式变化。必须指出变化进入真实使用后，减少或增加了哪一步。

### 落差

适合宣传、跑分、演示与真实效果不一致的内容。把承诺、成立条件和实际结果放在同一条证据链上。

落差不等于翻车。条件不同、指标不同和产品尚未成熟，需要分别说明。

### 机制

适合论文、架构、智能体流程和技术概念。围绕“它为什么能做到，依赖什么，又在哪里会失效”展开。

不要按术语顺序介绍。先给读者一个需要解释的结果，再逐层打开机制。

### 后果

适合安全、隐私、就业、组织管理、平台治理和责任问题。围绕“谁获得了什么能力，谁承担新的成本，什么结果难以撤回”展开。

不要从一次个案直接推导整个行业。先写清个案支持到哪一步。

### 人的处境

适合开发者、创作者、员工、管理者和普通用户的真实体验。围绕一个具体动作、犹豫、判断或工作变化展开。

不要把所有 AI 内容都写成职业焦虑，也不要虚构人物心理来增加温度。

## 第三步：构造强钩子

AI 文章也需要争夺注意力。克制不等于平淡，准确也不等于从背景讲起。

使用以下关系构造开头：

> 强钩子 = 可核验的异常事实 × 尚未解释的认知缺口 × 与读者有关的后果

三项不必全部塞进第一句话，但应在首屏内形成完整张力：读者已经知道发生了什么，也清楚还有哪个关键问题没有被解释，并能感觉到答案会改变自己的理解、工作、选择或风险判断。

### 先选择一种钩子

- **结果反转**：先交付与目标相反、与常识冲突或难以撤回的结果。
- **能力越界**：写清 AI 原本只是辅助，现在开始替人做出哪一步判断或操作。
- **控制权转移**：指出审批、选择、审核或执行权从人转移到了什么系统。
- **小变化，大后果**：从一个按钮、权限、接口、默认设置或工作步骤，写出它改变的真实关系。
- **承诺与条件并置**：把最吸引人的宣传承诺和最容易被忽略的成立条件放在相邻位置。
- **反直觉数字**：使用一个会改变判断的数字，并立刻说明比较对象与口径。
- **人的困境**：从一个具体使用动作、失误、等待、返工或无法回退的后果进入。
- **新瓶颈**：先写效率提升之后，真正变慢、变贵或变危险的另一环。

选择与主角度最接近的一种，不把多种钩子堆在一起。没有可靠异常事实时，使用清楚的问题或现实处境，不制造“震惊”和“翻车”。

### 首屏完成四个动作

1. **第一句交付张力**：直接写异常动作、结果、原话、数字或反差，不先介绍公司历史和行业背景。
2. **第二步给最低背景**：只补足读者理解这件事所需的人物、产品和条件。
3. **第三步打开缺口**：指出表面答案解释不了的地方，让读者知道接下来需要追哪一个问题。
4. **第四步建立利害**：说明这个问题会影响谁的控制权、效率、成本、责任或现实选择，但暂不把全部答案说完。

标题和首句不要重复同一句信息。标题负责打开问题，首句应立即增加新的事实或反差。前三段之后直接进入叙事或解释，不继续维持预告语气。

### 建立兑现节奏

钩子不是隐瞒答案，而是把答案拆成有因果关系的几步：

- 开头交付异常事实与待解释的问题。
- 正文前段给出第一层答案，让读者确认这不是空悬念。
- 中段完成核心机制、证据或结果的兑现。
- 后段解释条件、后果与仍然未知的部分。

已经公开的关键结果可以先说。真正让人继续读的，不一定是“结果是什么”，也可以是“为什么会这样”“它改变了什么”或“谁会承担后果”。

每一节结束时，检查刚刚揭示的事实是否自然产生了下一个问题。下一节负责回答这个问题，不使用“接下来更精彩”“真正的重点还在后面”等人工预告。

### 钩子护栏

不要使用“最近有一条新闻”“今天聊聊”“这篇文章说”“素材里提到”“你敢相信吗”“AI 又变天了”之类的开场。成稿应直接进入事件或问题，不暴露加工过程。

不要通过以下方式换取停留：

- 故意隐去已经公开且理解全文必需的结果。
- 把正常版本更新写成行业颠覆。
- 把条件差异包装成公司翻车。
- 使用无法由正文兑现的职业焦虑、失控风险或淘汰预言。
- 第一段连续反问，却没有一个具体事实。
- 用“震惊、炸裂、可怕、所有人都错了”替代认知落差。

强钩子依赖事实密度、未完成理解和现实利害，不依赖感叹号与营销音量。

## 第四步：守住事实分层

AI 内容至少区分以下层次：

1. **已发生的事实**：发布、时间、功能、操作、实验设计和公开结果。
2. **来源一方的主张**：公司、作者或研究团队声称的能力与意义。
3. **外部验证**：第三方测试、用户反馈、复现结果或相反证据。
4. **作者判断**：对机制、条件、影响与后果的解释。
5. **仍然未知**：尚无数据、无法核验或需要时间观察的部分。

不要用流畅句子抹平层次。使用“官方称”“研究在这一条件下发现”“现有证据只能说明”“更准确地说”等自然归属，但避免每句都堆免责声明。

数字必须进入关系：不要孤立罗列参数、跑分和百分比，要说明它与什么相比、在什么条件下测得、改变了什么判断。

## 第五步：把技术解释成人能理解的关系

解释技术时遵循：

> 可见结果 → 中间机制 → 依赖条件 → 失败边界 → 对人的影响

优先回答：

- 它替谁完成了原本哪一步？
- 它需要读取什么、调用什么、保留什么状态？
- 判断权从谁转移给了谁或什么系统？
- 速度提升之后，新的瓶颈落在哪里？
- 出错时能否发现、停止、回退和追责？

术语首次出现时，用一句自然中文说明它在当前语境里做什么。只保留支撑主角度所需的原理，不为证明专业而展示全部技术细节。

类比只用于解释结构相似处，并立即说清边界。一个好类比足够；不要让比喻代替机制，也不要连续堆叠宏大隐喻。

不默认插入 Mermaid、流程图或表格。只有用户明确要求，或复杂关系确实无法用简洁文字说明时，才另行提供；文章正文仍应能够独立读懂。

## 第六步：让判断从事实后面长出来

每一轮分析尽量遵循：

> 事实或细节 → 观察 → 为什么 → 成立条件 → 对谁有影响

先让读者看到，再解释这意味着什么。不要先宣布“本质上”“真正的问题是”“一个新时代已经到来”，然后把事实当作装饰。

判断需要可校准：

- 一个演示只能证明演示中的能力。
- 一次基准测试不能自动代表真实工作。
- 单个用户案例不能代表普遍采用。
- 官方路线图不是已经交付的产品。
- 技术可行不等于成本可接受、组织可用或责任清楚。
- 没有反例和适用条件的鲜明结论，通常只是更响亮的宣传。

允许明确表达个人观察，例如“我更在意的是”“真正让我停下来的，是这个细节”。一篇文章使用一到两次即可。个人风格来自选择了什么细节和追问，不来自反复写“我觉得”。

## 第七步：把变化落到人和组织

技术变化只有进入某个真实关系，读者才能感到它的重量。根据主角度选择一个落点：

- 普通用户多获得或失去了什么控制权。
- 开发者少做了什么，又多承担了什么审核工作。
- 创作者的门槛、速度、同质化或判断成本如何变化。
- 管理者把效率提升换成了什么新的治理责任。
- 企业的瓶颈从生产转移到了验证、协作、权限或分发中的哪一处。
- 某个错误由谁发现，谁能回退，最终由谁负责。

“回到人”不是强行煽情，也不等于每篇都讨论失业。它只是回答：这项抽象变化最终由谁经历，又以什么形式被经历。

## 第八步：兑现参与冲动

如果上游角度已经确定参与冲动，沿用它，不在写作阶段另加机关。每篇只保留一个主要冲动，最多一个辅助冲动：

- 想看结果：尽早说明读者在等待什么，并在中段或转折处兑现。
- 想辨真伪：清楚区分已确认、来源主张、外部验证与未知。
- 想看落差：还原承诺为什么在真实条件里缩小或失效。
- 想纠正：提供具体、可核验且有适用边界的判断，不故意留错。
- 想支招：写清目标、限制和取舍，让经验可以真正进入。
- 想代入：提供具体工作或生活场景，不点名要求读者代入。
- 想证明自己：留下可比较的条件和经验差异，不设计优越感陷阱。
- 想转发：形成一句准确、可复述、脱离上下文仍有边界的判断。

没有自然参与空间时，宁可不设计。认知价值和事实信任优先于评论欲。

## 第九步：组织正文

结构服务于推进，不按固定模板填格。根据素材选择：

### 单一事件或产品更新

异常细节或结果开头，补足发生过程，解释真正变化的一层，再落到使用场景、条件与后果。

功能列表只保留与主角度有关的部分。不要从发布稿第一项写到最后一项。

### 一篇博客、访谈或论文观点

从最值得停下来的判断或结果进入，还原它依赖的推理与证据，再说明作者没有充分处理的条件、现实位置或读者决策。

不要按原文目录复述，也不要让正文出现“下面总结原文”。

### 一个主案例加辅助案例

主案例承担完整叙事和主要篇幅。辅助案例只用于证明、对照或补充条件，每个案例都要回答“它为主判断增加了什么”。

### 素材簇

用最有画面的事实进入，在两到三个案例后命名共同结构，然后解释差异、边界与现实后果。不要写成新闻合集，也不要为了制造趋势堆砌十条相似事件。

### 观点评论

先准确复述需要回应的具体判断，再给出赞同、修正或反对的理由。争论对象是条件、证据与后果，不是人物动机和阵营身份。

## 第十步：控制语言、句子与段落

默认语言温度是八分冷静，两分情绪。情绪只在异常细节、真实代价和关键转折处升高，随后回到事实。

- 以完整自然的中文短句和中句为主，用较长句完成复杂关系。
- 每段通常一到四句，一个段落只推进一个动作或判断。
- 关键句可以独立成段，但不要每句话都换行。
- 连续两三个短句后，用完整长句恢复叙述。
- 优先使用具体名词、动词、数字和后果，减少程度副词。
- 允许一处轻微冷幽默或闲笔，不解释笑点。
- 专有名词保留官方写法，中文解释比缩写更重要时先写中文。

谨慎使用：

- “不是……而是……”只在真的需要修正错误理解时使用。
- 排比只在信息具有真实递进时使用，不连续制造金句。
- 反问需要文章已经给出足够事实，不能替代论证。
- 破折号、括号和引号用于澄清关系，不用于制造表演感。

不要写成：

- 发布会通稿：全球领先、重磅升级、全面赋能。
- 营销口播：重点来了、你敢信吗、一定要看到最后。
- 模板科技文：首先其次最后、机遇与挑战并存、未来可期。
- 情绪评论：可怕、炸裂、细思极恐，却没有具体后果。
- 伪深度文：堆叠范式、重构、颠覆、底层逻辑而不解释关系。
- 翻译腔：保留英文原句结构，中文读起来像术语拼接。

## 第十一步：标题、章节与结尾

默认输出 Markdown 成稿。

- 使用一个 H1 标题。
- 长文通常使用三到五个 H2；短文可不设小标题。
- H2 优先使用简洁中文序号，或真正提供定位的短标题。
- 正文以自然段为主，不把分析写成清单。
- 不插入图片占位符、编辑提示和写作说明。

标题从最有张力的事实、变化、原话或后果中提取。一般控制在十六到二十八个中文字，不为长度破坏自然表达。

避免“AI 又变天了”“所有人都低估了”“一篇文章看懂”“深度解析”“彻底颠覆行业”等大于证据的承诺。标题可以留下问题，但正文必须能够兑现。

结尾选择一种即可：

- 回到开头的细节或动作。
- 停在某个具体后果上。
- 给出一条带条件的清楚判断。
- 把镜头落到一个人的现实选择。
- 留下素材本身尚未解决的问题。

不要总结全文，不写“这件事告诉我们”“未来让我们拭目以待”“你怎么看”“评论区见”。好的结尾像把镜头停住，不像主持人宣布结束。

## 第十二步：执行三轮修订

### 事实与归属

- 核对名称、版本、时间、数字、原话和事件顺序。
- 区分事实、官方主张、外部验证、作者判断和未知。
- 删除无法由材料确认的心理、因果和场景。
- 检查标题是否大于正文证据。

### 角度与结构

- 用一句话复述主角度，确认中途没有换题。
- 检查每一节是否带来新事实、新解释或新后果。
- 删除与主角度无关但显得专业的技术旁支。
- 检查核心参与冲动是否完成兑现，没有制造假悬念。
- 检查首屏是否同时建立异常事实、认知缺口与读者利害。
- 检查正文前段是否已经交付第一层答案，中段是否兑现核心问题。
- 检查文章是否真正回答了“这与谁有什么关系”。

### 语言与节奏

- 删除新闻摘要、发布会通稿、教程和营销口播语气。
- 删除重复判断、段末小结和无信息量金句。
- 把抽象形容词换成动作、数字、条件或结果。
- 调整连续相同句式和过碎段落。
- 默读开头、技术解释、转折与结尾，确认中文自然。

只修改没有通过的部分，不因为一句不顺而重写已经成立的全文。

## 常见失败诊断

- **开头没有抓力**：删除背景前言，从结果、控制权转移、反直觉数字或新瓶颈中选择一个进入。
- **钩子只有情绪**：删除震惊和反问，补入可核验的动作、数字、原话或后果。
- **开头很强，正文泄气**：让首屏提出的唯一问题成为正文主线，在前段先兑现一层答案。
- **一直吊着不回答**：提前公开已知结果，把悬念转移到原因、机制、条件或后果。
- **像新闻摘要**：删去按时间和功能逐项复述，提前交付异常细节与真正变化。
- **像产品说明**：把“有什么”改写为“替谁改变了哪一步，又增加了什么条件”。
- **像技术教程**：减少操作步骤，只保留支撑主判断的机制。
- **准确但没有人**：补入真实使用场景、判断权、责任或后果，不虚构人物故事。
- **有人但没有技术**：补回决定结果的机制与条件，不用情绪替代解释。
- **观点太大**：缩回单个产品、案例、工作流或已被证据支持的范围。
- **观点很硬但不像自己**：删除为了显得鲜明而制造的态度，回到最初在意的细节。
- **全是“不是而是”**：保留一次真正的认知修正，其余改成直接陈述。
- **像 AI 写的**：删除对称排比、三段式小结、万能金句和无风险结论，恢复事实推进。
- **有术语没有解释**：写清术语在当前关系里做了什么。
- **有类比没有机制**：补回真实因果与边界，必要时删除类比。
- **强行谈失业或时代**：回到具体角色今天多做或少做的那一步。
- **结尾像总结**：删除最后一段，尝试停在前一个具体画面或判断。
- **出现“这篇文章”或“素材里”**：删除加工过程，直接讲事件、观点或注明具体来源。

## 篇幅控制

用户指定篇幅时遵循用户要求。未指定时，根据材料密度选择：

- 单一资讯或产品更新：约一千二百到一千八百个中文字。
- 单一事件或观点评论：约一千六百到二千四百个中文字。
- 有充分证据的多材料长文：约二千二百到三千五百个中文字。

这些范围是编辑预算，不是凑字指标。材料不足时主动缩短；主角度完成后及时结束。需要更长篇幅时，新增的每一节都必须提供新证据、新机制、新边界或新决策价值。

## 输出格式

默认只输出可以继续编辑的 Markdown 成稿：

```markdown
# 标题

开头正文。

## 一

正文。
```

不要在正文前添加角度分析、写作策略、字数统计或改写说明，也不要在正文后添加自检报告。用户明确要求分析、备选标题或修改说明时，再单独提供。

存在影响结论成立的事实缺口时，先完成能够安全写出的部分，再用一句简短说明列出待确认项，不把编辑风险混进正文。

修改现有稿件时，默认只交付修改后的完整稿。用户明确要求对照时，再解释改动。

## 最终自检

- 是否沿用唯一主角度，没有擅自重新选题？
- 是否从具体异常事实进入，而不是从背景或宏大判断开始？
- 首屏是否建立认知缺口与读者利害，让人清楚为什么继续读？
- 正文是否及时兑现钩子，没有隐瞒已知结果或制造假悬念？
- 是否区分事实、来源主张、外部验证、作者判断和未知？
- 是否把技术机制写成可理解的关系，同时保留必要条件？
- 是否让判断从事实后面长出来？
- 是否明确这项变化由谁经历，以什么方式经历？
- 是否只保留一个主要参与冲动，并完成兑现？
- 是否避免新闻摘要、通稿、教程、口播和模板议论文语气？
- 是否没有编造人物、心理、数字、场景、因果和趋势？
- 是否只翻开一层，没有用大词掩盖证据不足？
- 标题是否与证据相称，结尾是否自然停住？
- 输出是否为干净 Markdown 成稿，没有暴露加工过程？

用一句话概括本技能：

> 把技术写清楚，把变化写具体，把判断留在证据能承受的位置，最后让读者看见这件事与谁有关。
