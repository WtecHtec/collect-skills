# TTS 中文口播文案

## 核心目标

生成一份无需人工清理，能够直接粘贴给 TTS 模型的中文口播稿。

优先级依次为：

> 读得对 → 听得懂 → 念得顺 → 保留风格

不要为了文学感牺牲发音稳定，也不要把口语化理解成网络黑话。保持表达清楚、自然、克制，像一个人在认真把事情讲明白。

默认只设置一道硬边界。单篇口播正文不得超过一千二百字符，除非用户明确提供了更严格的引擎上限。不要为了追求短而破坏内容完整性。

## 识别输入

根据输入执行最小必要流程：

- 用户给出素材：先确定唯一表达重点，再写口播稿。
- 用户给出完整文章：吸收内容并提炼一条口播主线，不逐段缩写全文，也不在成稿中说明内容来自文章。
- 用户给出短文成稿：保留原意，重点处理口语节奏与 TTS 兼容性。
- 用户给出选材或短篇 Skill 的结构化结果：使用素材、人的抓手、个人观察和风险，不输出这些字段名称。
- 用户指定字符上限：严格遵循该上限；未指定时使用一千二百字符硬上限。
- 用户指定时长：按时长控制内容密度，但不能突破字符上限。
- 用户未指定时长：选择能完整表达内容的自然长度，不为接近上限而扩写。
- 用户指定 TTS 引擎、SSML 或字符规范：优先遵循用户给出的引擎规则。

默认只生成中文普通话口播。不要凭空增加音效、镜头、字幕或表演指令。

除非用户明确要求平静叙述、新闻播报或其他节奏，默认使用强开头。这里的强，不是提高音量或夸大情绪，而是尽快交付真正有吸引力的信息。

## 第一步：确定唯一表达动作

先在内部完成一句话：

> 听众听完后，只需要明白或感受到________。

只选择一个动作：

- 讲清一个事实或变化
- 修正一个容易误解的判断
- 讲出一个人物或场景
- 保留一个有趣的反差
- 准确命名一种处境或感受
- 给出一个具体、可执行的提醒

口播稿同时承担多个动作时，缩小主题或拆成多条。不要把背景、观点、建议和总结全部塞进一分钟。

## 第二步：建立口播结构

根据素材选择一种结构。

### 清楚说明

> 直接进入事实 → 补必要背景 → 说清真正变化 → 克制结束

适合资讯、产品、事件和观点。

### 轻分享

> 最少铺垫 → 呈现原话、动作或反差 → 在最好听的位置停下

适合娱乐素材、生活观察、人物片段和视觉发现。不要解释笑点，也不要强行上升。

### 小故事

> 人物正在做什么 → 出现一个变化 → 后果落到人身上 → 留下余味

适合人物经历、关系、创作和真实场景。

### 实用提醒

> 先说问题 → 给出一到三个动作 → 补一个必要边界 → 结束

适合教程、避坑和使用建议。步骤超过三个时，拆分内容。

## 第三步：建立强开头

第一句就是前三秒钩子。按中文 TTS 正常语速估算，首句优先控制在十二到十八个可朗读单位。可朗读单位指实际会被念出的汉字、字母和数字，不统计空格与标点。专有名词较长时可以略微放宽，但必须保持一口说完。

首句只选择一种主要情绪，不要同时堆叠：

- 猎奇：熟悉场景里出现一个反常动作。
- 反差：很小的目标，带来明显越界或相反结果。
- 震惊：先交付已经发生的严重结果。
- 不安：先交付不可逆、无法控制或责任不明的后果。

钩子必须由事实产生。首句直接说最异常的动作或结果，至少包含具体对象、具体动作和反常之处中的两项。第二句立即补上后果、反转或关键事实，让听众知道第一句不是夸张。第三句再补人物、时间、机构或事情起因等必要背景。

优先使用以下结构：

- 小目标加异常手段。例如，只想抢一节课，A I 却踢掉了别人。
- 结果先行。例如，一个本该私下分享的页面，被所有人搜到了。
- 不可逆结果。例如，A I 完成操作后，只说无法恢复。
- 熟悉场景加反常动作。例如，图书馆为了提高借阅量，先撤掉了座椅。

问题句只有在问题本身已经包含具体事实时才使用。优先写陈述句，因为它能更快交付信息。

强开头必须忠于素材。不要使用以下方式：

- 欢迎语、自我介绍和今天聊聊
- 你知道吗、你敢信吗和绝对想不到
- 出大事了、太可怕了和改变所有人等空泛判断
- 先别划走、一定要看到最后和关注我
- 故意隐去关键事实，只制造没有内容的悬念
- 为了情绪删除重要条件，把可能、争议或单方说法写成确定事实

第一句完成吸引，第二句完成兑现，第三句进入叙事。后文恢复清楚、克制的表达，不让整篇都维持高刺激语气。

## 第四步：按听觉改写

写给耳朵，不写给眼睛。

口播要站在事件和观点内部直接讲述，不保留加工过程。默认删除以下来源容器表达：

- 这篇文章讲了
- 文章还提到
- 原文写道
- 素材里说
- 作者接着表示
- 从这段内容可以看出

需要保留事实归属时，使用具体主体与动作，例如公司公布、研究人员发现、当事人表示或公开记录显示。不要用文章、原文、素材和作者代替真正的信息来源。

- 每句话只承担一个主要意思。
- 先说主体，再说动作，减少多层倒装。
- 把长定语拆成两个短句。
- 把抽象名词改成具体动作或结果。
- 代词可能指向不清时，重复人物或对象名称。
- 省略视觉上可回看的复杂并列，改成顺序表达。
- 一个专业词出现后，用一句自然中文解释，不连续堆术语。
- 开头直接进入人物、动作、变化或问题，不写欢迎语和空泛预告。
- 结尾完成当前动作即可，不重复全文，也不强行号召关注。

建议每个分句约十二到二十八个中文字。句子过长时，在自然语义边界拆开，不用逗号无限续接。

## 第五步：控制字符与时长

### 字符上限

- **默认硬上限**：一千二百字符。最终口播正文不得超过这一数值。
- **用户上限**：用户指定更短上限时，以用户上限为准。
- **引擎上限**：用户明确提供其他 TTS 限制时，以更严格的一项为准。

字符数以最终归一化后的口播正文为准。统计所有中文、英文字母、空格和标点，只排除换行符。字母之间为了稳定朗读而加入的空格也计入字符数。

超过上限时，按以下顺序压缩：

1. 删除第二观点和旁支背景。
2. 删除重复解释与总结。
3. 缩短例子，只保留一个具体细节。
4. 把长专有名词替换为已经说明过的稳定简称。
5. 保留唯一表达动作与必要事实边界。

超过一千二百字符时，不得直接交付。优先收紧主题并删减旁支。用户明确要求完整保留、且单篇无法容纳时，拆成多篇独立口播稿，每篇重新执行字符与 TTS 检查，不在正文中加入第一篇、第二篇等会被读出的标签。

### 时长估算

未给定具体语速时，按每分钟约二百四十到二百八十个中文字估算：

| 目标时长 | 建议中文字数 |
|---|---:|
| 十五秒 | 五十五到七十字 |
| 三十秒 | 一百一十到一百四十字 |
| 四十五秒 | 一百六十五到二百一十字 |
| 六十秒 | 二百二十到二百八十字 |

这些数字只用于编辑预算。专有名词多、需要明显停顿或语速较慢时，主动减少字数。无论目标时长如何，单篇都不能超过一千二百字符。不要为凑满时长添加重复总结。

## 第六步：限制标点与格式

默认口播正文只使用：

- 中文逗号 `，`
- 中文句号 `。`
- 中文问号 `？`，仅用于真正的问句
- 中文感叹号 `！`，仅在语气确实需要时使用，默认不用
- 换行，用于自然分段，不连续空行

默认移除或改写以下内容：

- 顿号、冒号、分号、单双引号
- 圆括号、方括号、书名号
- 破折号、省略号、斜杠、竖线
- 加号、等号、百分号、井号、星号、艾特符号
- Markdown 标题、列表符、代码块、链接和表格
- Emoji 与装饰符号
- 括号中的补充说明、发音提示和舞台指令

并列内容不要使用顿号。项目较少时改用中文逗号或 `和`、`以及`、`或者` 等自然连接词。项目较多时删减，只保留最能帮助理解的两到三项。

不要输出 `停顿`、`重读`、`语气上扬`、`笑` 等文字指令。用户明确要求某个 TTS 引擎支持的 SSML 时，再输出对应标签，并与纯文本版分开。

## 第七步：处理字母与英文

连续字母是 TTS 最容易不稳定的部分。先确定它应该被读成英文单词、逐字母拼读，还是中文名称。

### 缩写与首字母组合

逐字母朗读，并在字母之间加入空格：

- `AI` 改为 `A I`
- `TTS` 改为 `T T S`
- `API` 改为 `A P I`
- `GPT` 改为 `G P T`

不要保留两个或更多连续的大写字母。

### 混合产品名与模型名

按可发音单词和字母缩写拆分：

- `OpenAI` 改为 `Open A I`
- `ChatGPT` 改为 `Chat G P T`
- `GPT-5` 改为 `G P T 五`
- `GPT-4o` 改为 `G P T 四 O`

若所用 TTS 对英文单词读音不稳定，优先使用用户认可的中文名称或逐字母拼读。不要自行创造容易误导的音译。

### 英文句子与术语

- 有自然中文说法时，优先改成中文。
- 品牌、姓名和作品名必须保留时，拆清语义单元。
- 无法确定读法时，不猜测，在正文外提示用户确认。
- 不把网址、邮箱、文件路径、代码或账号直接塞进口播。只有内容必须依赖它们时，改成听得懂的说法。

## 第八步：处理数字、单位与符号

把视觉写法转换成预期读法。

### 常见转换

- `2026年8月12日` 改为 `二零二六年八月十二日`
- `14:30` 根据语境改为 `下午两点半` 或 `十四点三十分`
- `12%` 改为 `百分之十二`
- `3-5次` 改为 `三到五次`
- `2.5` 改为 `二点五`
- `¥199` 改为 `一百九十九元`
- `10km` 改为 `十公里`
- `5°C` 改为 `五摄氏度`
- `1:3` 根据语境改为 `一比三`
- `A/B测试` 改为 `A B 测试`，或改成 `对照测试`

### 按语义选择读法

- 年份逐位读，数量按中文数值读。
- 电话、编号和验证码通常逐位读。
- 小数保留 `点`。
- 百分比、货币、温度、距离和重量写出单位全称。
- 范围使用 `到`，比例使用 `比`，选择关系使用 `或者`。
- 版本号按产品习惯读，不确定时写成 `版本` 加清楚的数字读法。

正文中默认不保留阿拉伯数字和数学符号。若某个编号必须保持原样，在正文外单独提供给用户，不让 TTS 直接猜读。

## 第九步：处理易错发音

- 避免生僻字、罕见缩写和无法判断读音的人名。
- 多音字在当前句子里可能歧义时，换成意义相同但读音稳定的说法。
- 外国人名、品牌名和地名首次出现前，确认用户希望的读法。
- 同一个名称全稿使用同一种写法，不交替使用英文、缩写和中文译名。
- 不用括号或拼音在正文中标注发音，因为 TTS 可能把标注一起读出来。

无法确认专名读法时，保持内容工作继续进行，在正文后单独列出待确认项。不要为了规避读音问题而改动事实身份。

## 第十步：保持个人风格

- 保留清楚、克制和自然的中文。
- 不使用主持腔、新闻联播腔和营销播音腔。
- 不连续使用 `你知道吗`、`重点来了`、`更可怕的是` 等钩子。
- 强开头靠事实密度和具体动作，不靠营销口吻。
- 不用密集反问、排比和情绪升级制造节奏。
- 不把口语写成碎片；保持完整句子。
- 娱乐素材允许干净的冷幽默，但不解释笑点。
- 严肃素材只翻开必要的一层，不写成演讲。
- 允许重复关键对象以消除指代歧义，但不重复结论。

## 第十一步：执行 TTS 归一化

成稿完成后，按顺序检查：

1. 删除 Markdown 与非正文说明。
2. 将特殊标点改为逗号、句号或自然连接词。
3. 拆分连续大写字母与混合模型名。
4. 将阿拉伯数字、单位和符号改成预期读法。
5. 检查英文词、多音字、专名和代词歧义。
6. 删除文章、原文、素材和作者提到等加工痕迹。
7. 逐句默读，确认每句话一次能听懂。
8. 删除重复结论、强行升华与互动诱导。
9. 统计最终字符数，确保单篇不超过一千二百字符。
10. 单独检查首句，确认前三秒已经出现具体异常动作或后果，并且只承担一种主要情绪。
11. 检查第二句是否立即兑现钩子，第三句是否开始补充必要背景。

若文案保存为本地纯文本文件，运行：

```bash
python3 scripts/check_tts_text.py path/to/script.txt
```

脚本默认在超过一千二百字符时报错。修复所有错误，并逐项确认其他字符警告。脚本只检查字符风险，不替代人工默读。

## 事实与边界

- 改写发音形式时不得改变数字含义、人物身份、产品名称或事实归属。
- 资讯、日期、数据和争议说法沿用已核验来源；未核验时不要把它们写成确定事实。
- 原作者的独特表达需要归属时，点明具体作者或说话者，不使用原文提到等容器表达。
- 为了念得顺可以换句式，不能删掉影响结论的条件。
- 用户提供的隐私信息、账号、密钥和联系方式不得写入口播正文。

## 失败诊断

- **看得懂但听不懂**：缩短句子，先说主体，消除代词歧义。
- **像书面文章**：把长定语、括号补充和并列结构拆开。
- **像在转述一篇文章**：删除文章、原文、素材和作者提到等提示，直接讲事件；需要归属时改用具体主体。
- **像营销口播**：删除情绪钩子、悬念预告和号召关注。
- **前三秒没有钩子**：把最反常的动作或最严重的结果压缩到首句，并控制在十二到十八个可朗读单位。
- **钩子只有情绪没有事实**：删除震惊、可怕和没想到等判断词，换成具体对象、动作或后果。
- **钩子太挤**：只保留猎奇、反差、震惊或不安中的一种情绪，其他信息放到第二句以后。
- **开头进入太慢**：把人物背景放到第三句以后，第一句讲异常，第二句讲后果。
- **开头很用力但没有信息**：删除情绪形容词，补回人物、动作和后果。
- **TTS 误读字母**：拆分连续大写字母，确认英文词读法。
- **TTS 误读数字**：按年份、数量、编号、比例或版本的语义重写。
- **停顿太碎**：减少逗号，把同一意思合成完整句子。
- **仍然出现顿号**：改用逗号或自然连接词，并删减过长的并列项目。
- **一口气念不完**：在语义边界拆句，不增加特殊停顿符号。
- **解释过度**：保留唯一表达动作，删除第二层道理。
- **内容太短但不完整**：补必要背景，不用空泛总结凑长度。
- **超过字符上限**：删除旁支和重复解释；仍无法完整表达时拆成多个独立段落。
- **为了限字变得听不懂**：恢复必要主语和逻辑连接，再删除不重要的观点，而不是删除语义骨架。

## 输出格式

默认只输出一份可直接用于 TTS 的纯文本正文，字符数不得超过一千二百：

- 不加标题
- 不加 Markdown
- 不加项目符号
- 不加代码块
- 不附字数、时长、改写说明或发音注释

内容必须拆成多篇时，将每篇口播稿作为独立纯文本块交付。标签放在正文之外，确保复制单个文本块时不会把标签交给 TTS。每篇单独遵守一千二百字符上限。

用户明确要求时，才在正文之后分开提供：

- 预计时长与中文字数
- 专有名词读法清单

## 最终自检

交付前确认：

- 是否只保留一个表达动作？
- 首句是否能在前三秒说完，并交付具体异常动作或后果？
- 首句是否只选择猎奇、反差、震惊或不安中的一种主要情绪？
- 第二句是否立即兑现钩子，第三句是否开始补背景？
- 强开头是否忠于素材，没有空悬念和夸张结论？
- 每句话是否一次就能听懂？
- 是否只使用允许的中文标点？
- 是否没有顿号，并已把并列项改成自然口语？
- 是否没有 Markdown、Emoji、括号和舞台指令？
- 是否没有文章、原文、素材和作者提到等加工痕迹？
- 是否拆分所有连续大写字母？
- 是否将数字、单位与符号写成预期读法？
- 是否确认英文词、专名和多音字的读法？
- 最终口播正文是否不超过一千二百字符？
- 是否保留必要事实条件与归属？
- 是否在恰好的位置结束，没有重复总结或号召关注？

用一句话概括本技能：

> 不只把内容写出来，还要把每一个字写成能被稳定念出来的样子。
