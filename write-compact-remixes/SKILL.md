# 克制短篇二创

## 核心目标

把一个二创角度写成最小但完整的内容单元。

不要机械压缩长文，也不要模仿特定平台的流行格式。短篇只完成一个动作：让读者看懂一点、修正一个判断、认出一种感受、注意一个画面，或建立一处连接。

遵循核心结构：

> 一个具体细节 → 翻开隐藏的一层 → 留下一个判断或余味

保持默认风格：完整、自然、克制；不使用一词一行的机械断句，不靠夸张标题、平台套话和强行反常识制造存在感。

## 识别任务

根据输入执行最小必要流程：

- 用户已经给出二创角度：直接进入短篇设计，不重新生成多个角度。
- 用户只给素材：先提炼一个最自然的主角度，再写短篇。
- 用户给出长文：选择其中一个能够独立成立的内容单元，不做全文摘要。
- 用户给出短稿：判断它缺少具体细节、隐藏一层还是落点，再进行改写。
- 用户指定长度：在不破坏完整性的前提下遵循。
- 用户未指定长度：根据信息密度选择最短的完整形式。
- 用户要求多个版本：保持内容动作一致，按不同表达密度展开。

不要在用户只要求短篇时扩展为完整长文。

## 第一步：确定唯一内容动作

先完成一句话：

> 读者读完后，只需要多获得________。

从以下动作中只选一个：

- **看懂**：澄清一个容易误解的概念、变化或关系。
- **修正**：补充一个条件、边界、代价或反例。
- **认出**：准确命名一种处境、矛盾或情绪。
- **看见**：让一个细节、动作、物件或画面变得可见。
- **连接**：把当前素材与另一段经历、作品或长期变化联系起来。

如果一篇短文同时想完成三个动作，缩小角度或拆成多条。

## 第二步：建立短篇三点卡

写作前只保留三项：

1. **进入细节**：一个事实、句子、动作、场景、物件或反差。
2. **隐藏一层**：该细节背后的机制、条件、情绪、选择或关系。
3. **最终落点**：希望读者带走的判断、感受、画面或问题。

三项之间必须存在自然的因果、判断或情绪推进。不要用口号连接逻辑断点。

## 第三步：选择短篇形态

### 短判断

结构：事实或原话 → 补充条件 → 克制结论。

适合资讯、产品、职场、争议观点和现实选择。

### 短观察

结构：具体细节 → 意外连接 → 仍值得追问的一层。

适合社会、设计、生活、趋势和日常发现。

### 短共鸣

结构：具体场景 → 被忽略的感受 → 准确命名或留白。

适合人物经历、创作、关系和个人成长。

### 短画面

结构：一个物件或动作 → 它承载的变化 → 画面式结尾。

适合摄影、电影、音乐、设计、人物和情绪内容。

选择最符合素材真实反应的形态，不要默认所有内容都需要判断。

## 第四步：选择表达密度

根据内容需要选择形式，不根据发布平台选择。

### 一句话

默认长度：30～80 个中文字。

只保留一个已经成立的观察、判断或画面。不要把缺少依据的口号包装成金句。

适合：

- 原素材中已经存在足够具体的细节
- 隐藏一层可以被压进同一句或相邻两句
- 不需要额外背景也能理解

### 微短文

默认长度：80～180 个中文字。

使用一个自然段，必要时分为两个短段。完整呈现进入细节、隐藏一层和最终落点。

适合：

- 一个事实需要被重新理解
- 一个观点需要补充条件
- 一个场景能够承载一种感受

### 小短文

默认长度：180～500 个中文字。

使用两至四个自然段。允许增加一个具体过程、对比或例子，但不得发展出第二主角度。

适合：

- 读者需要少量背景才能理解
- 隐藏一层包含完整的因果或情绪变化
- 结尾需要从事件回到人的处境

这些长度是编辑预算，不是硬性字符上限。内容在更短形式中无法完整成立时，选择下一档；能够更短说清时，不为凑字数扩写。

## 第五步：写出最短完整版本

按以下顺序写：

1. 直接呈现进入细节，不写泛泛背景。
2. 只翻开一层，不罗列全部分析。
3. 完成唯一内容动作，不重复总结。

先写清楚，再缩短。不要一开始就用省略、跳步和碎片化语言追求短。

## 第六步：执行减法

按以下顺序删除：

1. 与主角度无关的背景
2. 第二个和第三个观点
3. 重复解释同一件事的句子
4. 不能推进内容的案例
5. “我觉得”“值得注意”“这意味着”等标签词
6. 为了显得完整而添加的总结
7. 删除后不影响主角度的形容词和连接词

不要删除：

- 触发内容的具体细节
- 事实来源和必要限定
- 从细节到隐藏一层的逻辑铰链
- 让短篇真正结束的落点

短不等于跳步。删到逻辑断裂时，恢复必要句子或选择更长一档。

## 第七步：生成不同密度版本

用户要求多个版本时，以同一个三点卡为核心：

- 一句话版只留下最集中的观察或画面。
- 微短文版补回必要的逻辑铰链。
- 小短文版增加一个具体过程、例子或人的处境。

不同版本必须共享同一个进入细节、隐藏层和最终落点。不要通过增加第二观点制造“更长版本”。

## 事实与来源

保留短篇仍然需要的事实边界：

- 原作者说法使用“作者认为”“原文提到”等自然归属。
- 产品发布、数据、日期和人物身份优先核验原始来源。
- 个人经历和评论区反馈只作为场景样本。
- 不确定性来自证据不足时，明确说明，不用模糊语气掩盖。
- 短篇不能因为篇幅有限而把一方口径写成公认事实。

## 风格护栏

- 使用完整中文句子与自然段落。
- 不把一句完整逻辑拆成多个单词行。
- 不使用连续排比、整齐对仗和密集反问制造节奏。
- “不是 A，而是 B”最多偶尔使用一次，优先把对比融入叙述。
- 不用“值得注意的是”“有趣的是”“这意味着”预告观点。
- 不靠“我觉得”制造个人性；让选择的细节和落点体现风格。
- 不把克制理解为没有态度。该明确时给出具体判断。
- 不把共鸣写成空泛抒情；至少保留一个可感知的场景或动作。
- 不要求每篇内容提供建议、教程或宏大意义。
- 不模仿平台黑话、引流句、热门标题或标签堆砌。
- 允许一句自然闲笔，但不能破坏短篇唯一动作。

## 失败诊断

- **像长文摘要**：丢弃全文覆盖目标，只选择一个能够独立成立的片段。
- **文字很短但没说完**：补回细节与隐藏层之间的逻辑铰链。
- **像口号或金句**：增加事实、动作或具体场景。
- **观点过多**：保留最接近最初反应的一条，其余另存选题。
- **多个长度版本只是增删句子**：重新确认三点卡，并让更长版本增加过程而非新观点。
- **内容偏技术**：检查是否可以落到人的使用、选择、感受或观看方式。
- **情绪很多但没有抓手**：加入一个具体句子、物件、动作或时刻。
- **为了短而语气生硬**：恢复自然语序，必要时选择更长一档。

## 输出格式

根据用户要求选择最少但完整的交付。默认只输出可直接使用的成稿；内容动作、三点卡、字数与事实检查都在内部完成，不主动展示。只有用户明确要求分析、字数、依据或编辑说明时，才补充相应信息。

### 单一短篇

输出：

1. 可直接使用的正文
2. 用户明确要求时，再附短篇形态、中文字数或一句编辑说明

### 密度阶梯

输出：

1. 一句话版
2. 微短文版
3. 小短文版

只用密度名称区分版本，不添加平台名称。不要主动输出“唯一内容动作”“三点卡”“事实说明”等过程信息，也不要把编辑说明混进可使用正文。若存在必须告知的事实风险，在正文之后单独简短提示。

### 长文切片

先列出 2～4 个可以独立成立的短篇单元。每个单元使用不同内容动作，避免把长文连续截段发布。用户只要求一个版本时，推荐最有独立价值的一条。

## 最终自检

交付前确认：

- 是否只完成一个认知或情绪动作？
- 是否包含具体细节、隐藏一层和最终落点？
- 删除原素材后，短篇是否仍可独立理解？
- 是否属于重新选择信息，而非压缩长文？
- 是否使用完整自然段落，没有机械断句？
- 是否保留必要的事实归属和限定？
- 长度是否由表达密度决定，而非平台模板？
- 结尾是否真正结束，没有重复总结或强行升华？

用一句话概括本技能：

> 只留下一个值得说清的动作，把它写短，但不要把它写薄。
